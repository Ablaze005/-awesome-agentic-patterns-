# Persistent Agent Memory with Supabase and pgvector

This example gives an agent a small, persistent memory store. It saves text as
embeddings in Supabase and retrieves the most similar memories when a new
message arrives.

## Overview

An agent without memory only knows what is in its current prompt. Persistent
memory lets it recall useful facts, previous conversations, or learned
preferences after the process has restarted. Supabase provides a hosted
Postgres database, while `pgvector` stores and searches embedding vectors.

The example uses OpenAI's `text-embedding-3-small` model. It stores two
memories, searches for memories related to a question, and prints the results.

## Supabase setup

### 1. Create a project

1. Sign in at [supabase.com](https://supabase.com).
2. Select **New project**, choose an organization, and enter a project name and
   database password.
3. Wait for the project to finish provisioning.
4. Open **Project Settings > API** and copy the **Project URL** and an API key.

### 2. Enable pgvector and create the schema

Open **SQL Editor** in the Supabase dashboard, create a new query, and run:

```sql
create extension if not exists vector;

create table if not exists agent_memories (
  id bigint generated by default as identity primary key,
  content text not null,
  embedding vector(1536) not null,
  metadata jsonb not null default '{}'::jsonb,
  created_at timestamptz not null default now()
);

create index if not exists agent_memories_embedding_idx
on agent_memories
using ivfflat (embedding vector_cosine_ops)
with (lists = 100);

create or replace function match_agent_memories(
  query_embedding vector(1536),
  match_threshold float,
  match_count int
)
returns table (
  id bigint,
  content text,
  metadata jsonb,
  similarity float
)
language sql
stable
as $$
  select
    agent_memories.id,
    agent_memories.content,
    agent_memories.metadata,
    1 - (agent_memories.embedding <=> query_embedding) as similarity
  from agent_memories
  where 1 - (agent_memories.embedding <=> query_embedding) >= match_threshold
  order by agent_memories.embedding <=> query_embedding
  limit least(match_count, 50);
$$;
```

For a quick local demonstration, the API key must be allowed to read and
insert rows. In **Authentication > Policies**, add appropriate `select` and
`insert` policies for `agent_memories`, or use the following demo-only policy
setup:

```sql
alter table agent_memories enable row level security;

create policy "demo can read memories"
on agent_memories for select
to anon, authenticated
using (true);

create policy "demo can insert memories"
on agent_memories for insert
to anon, authenticated
with check (true);
```

Do not use these open policies in production. Restrict rows to the current
user or use a server-side service role key kept outside the client.

The `1536` dimensions in the table and function match
`text-embedding-3-small`. If you choose another embedding model, change both
the model and the vector dimension consistently.

## Environment variables

Set these variables before running the script:

```bash
SUPABASE_URL="https://your-project.supabase.co"
SUPABASE_KEY="your-supabase-api-key"
OPENAI_API_KEY="your-openai-api-key"
```

Install the dependencies:

```bash
pip install supabase openai
```

Then run:

```bash
python example.py
```

The script reads the Supabase and OpenAI values with `os.getenv`; it does not
hard-code secrets.

## How the code works

1. **Store embeddings:** `embed()` sends text to OpenAI and returns a list of
   1,536 floating-point values. `remember()` inserts the original text,
   embedding, and optional metadata into `agent_memories`.
2. **Similarity search:** `recall()` embeds the new query and calls the
   `match_agent_memories` Postgres function. The function uses cosine distance
   (`<=>`), converts it to similarity with `1 - distance`, filters by a
   threshold, and returns the closest rows.
3. **Use memory in an agent:** an application can call `recall()` before
   generating a response and place the returned `content` values in the
   agent's context. The example prints those recalled memories; this keeps the
   storage layer independent from any particular agent framework.

## Example output

The exact similarity scores depend on the embedding model, but the output will
look like this:

```text
Saved 2 memories.

Memories related to: What does the user prefer to drink?
- The user prefers oat milk in their coffee. (similarity: 0.86)
- The user is learning Spanish and practices every morning. (similarity: 0.31)
```
