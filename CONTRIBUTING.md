# Contributing to Awesome Agentic Patterns

Thank you for your interest in contributing to **Awesome Agentic Patterns** — a community‑driven collection of agentic workflows, tools, and automation patterns.  
We welcome contributions from developers of all experience levels. Whether you're fixing a typo or designing a new agent architecture, your work helps grow this project and the ecosystem around it.

---

## 🚀 Ways You Can Contribute

There are many ways to make meaningful contributions:

### 🧩 Add New Patterns
- Submit new agentic patterns  
- Provide real‑world examples  
- Add diagrams or architecture explanations  

### 🛠 Improve Existing Content
- Refine existing patterns  
- Add missing details  
- Improve clarity and readability  

### 📚 Enhance Documentation
- Fix typos  
- Add examples  
- Improve structure and formatting  

### 🔧 Improve Code Quality
- Clean up unused code  
- Add comments for complex logic  
- Improve consistency and formatting  

### 💡 Suggest Ideas
- Propose new patterns  
- Suggest improvements  
- Share insights from your own projects  

Every contribution matters — big or small.

---

## 📝 How to Submit a Contribution

Follow these steps to contribute:

1. **Fork** the repository  
2. **Create a new branch** for your change  
3. Add your pattern, fix, or improvement  
4. Submit a **Pull Request**  
5. A maintainer will review your PR  
6. Once merged, you will be added to our **Hall of Fame**  

We appreciate every contributor and aim to review PRs regularly.

---

## 📐 Contribution Guidelines

To maintain quality and consistency across the project:

### ✔ Pattern Requirements
- Clear description of the pattern  
- Code example or workflow snippet  
- Explanation of use cases  
- Limitations or considerations  

### ✔ Code Style
- Keep formatting consistent  
- Avoid unused imports  
- Add comments where needed  

### ✔ Documentation Style
- Keep explanations simple and readable  
- Use headings and lists for clarity  
- Add examples where helpful  

### ✔ Security & Safety
- Avoid dangerous shell commands  
- Do not expose secrets or tokens  
- Avoid modifying workflow files unless necessary
