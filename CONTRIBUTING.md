# Contributing to Awesome Agentic Patterns

Thank you for your interest in contributing to **Awesome Agentic Patterns** — a curated collection of AI agent design patterns, memory architectures, workflow templates, and integration examples for modern agent frameworks such as LangGraph, Autogen, Swarms, Supabase, pgvector, FastAPI, and more.

We welcome contributions from developers of all experience levels. Whether you're fixing a typo, adding a new workflow, or proposing a new agent pattern, your contribution helps strengthen the ecosystem.

---

## 🌟 How You Can Contribute

### 🧩 Add New Patterns
- Submit new agentic patterns  
- Provide real-world examples  
- Add diagrams or architecture explanations  
- Add workflow templates for LangGraph, Autogen, Swarms, etc.

### 🛠 Improve Existing Content
- Refine existing patterns  
- Add missing details  
- Improve clarity and readability  
- Update outdated examples

### 📚 Enhance Documentation
- Fix typos  
- Add examples  
- Improve structure and formatting  
- Add conceptual explanations or diagrams

### 🔧 Improve Code Quality
- Clean up unused code  
- Add comments for complex logic  
- Improve consistency and formatting  
- Add tests for workflows where applicable

### 💡 Suggest Ideas
- Propose new patterns  
- Suggest improvements  
- Share insights from your own agent projects

Every contribution matters — big or small.

## 🚀 Getting Started

### 1. Fork the Repository
Click the **Fork** button on GitHub to create your own copy.

### 2. Clone Your Fork
```bash
git clone https://github.com/<your-username>/awesome-agentic-patterns.git
```

### 3. Create a New Branch
```bash
git checkout -b feature/my-new-pattern
```

### 4. Make Your Changes
Add your pattern, workflow, or improvement.

### 5. Commit Your Work
```bash
git commit -m "Add new LangGraph workflow pattern"
```

### 6. Push Your Branch
```bash
git push origin feature/my-new-pattern
```

### 7. Open a Pull Request
Go to your fork on GitHub and click **New Pull Request**.

## 📐 Contribution Guidelines

### ✔ Pattern Requirements
Each pattern should include:
- Clear description  
- Code example or workflow snippet  
- Explanation of use cases  
- Limitations or considerations  
- Folder structure that matches existing patterns

### ✔ Code Style
- Keep formatting consistent  
- Avoid unused imports  
- Add comments where needed  
- Use descriptive variable names  
- Follow Python best practices

### ✔ Documentation Style
- Keep explanations simple and readable  
- Use headings and lists for clarity  
- Add examples where helpful  
- Include diagrams when possible

### ✔ Security & Safety
- Avoid dangerous shell commands  
- Do not expose secrets or tokens  
- Avoid modifying workflow files unless necessary  
- Ensure examples are safe and reproducible
